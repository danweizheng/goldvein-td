# 占位美术方案（Placeholder Art Scheme）

> **决策**：像素美术资产开发**暂缓**，改用**程序化占位美术**。
> **变更人**：主策划 ｜ **状态**：设计已定，待实现
> **影响**：策划案 §7.1/§7.2 与 M2 验收标准同步修订

---

## 1. 为什么这是个好决定

原方案要 258 个手绘资源（87 塔精灵帧 + 132 敌人帧 + 20 组特效…），**这是项目唯一一个"加 agent 也解决不了"的瓶颈**——agent 能出规格、能生成占位图，但画不出能上线的像素美术。

改成程序化占位后：

| 维度 | 原方案 | 占位方案 |
|---|---|---|
| 外部依赖 | 需要会 Aseprite 的人（或外包预算） | **零** |
| 阻塞风险 | 卡死 M2 的「正式像素美术」验收 | **消除** |
| 新增单位成本 | 每个单位要画 3 帧 | **零**（从 `units.json` 自动生成） |
| 可验证性 | "好不好看" 只能主观判断 | **可生成接触表 PNG，可客观评审** |
| 替换成本 | — | 换实现类，**不改调用方** |

**代价**：游戏在 M2–M4 阶段"不好看"。这是刻意的取舍——**先把玩法和数值做对，再谈包装**。数值问题（M2 的不可通关）已经比美术更紧迫地证明了这一点。

---

## 2. 核心设计：视觉编码规则

占位美术不是"随便画个色块"。它必须让玩家（和开发者）**在 48×48 像素里一眼分辨**关键属性。以下是冻结的编码规则。

### 2.1 塔：形状 = 系，尺寸/齿数 = 品阶

| 塔系 | 轮廓 | 基础色（H 值） | 含义 |
|---|---|---|---|
| `thief` 神偷 | ◆ 菱形 | 金 `#ffc832` | 核心经济塔，用金色呼应"钱" |
| `archer` 弓箭 | ▲ 三角 | 草绿 `#7ec850` | 廉价输出 |
| `mage` 法师 | ⬢ 六边形 | 青蓝 `#4aa8e0` | 辅助乘区 |
| `drill` 军训 | ■ 方形 | 砖红 `#c85a50` | 阻挡/卡位 |
| `beauty` 美女 | ● 圆形 | 紫粉 `#b06ee0` | 减速/群伤 |
| `cannon` 炮塔 | ⬣ 八边形 | 橙 `#e08a30` | 攻城/溅射 |
| `worker` 工人 | 小方块 + 缺口 | 灰 `#9a9a9a` | 建造/采集 |
| `sprite` 小精灵 | 3×3 点簇 | 木色 `#c8a050` | 产木 |
| `tech` 科技塔 | ✚ 十字 | 白 `#e8e8e8` | 科技解锁 |

**品阶 `tier` T1–T5 → 底部齿数 = tier**（1–5 个小方块），轮廓线宽 `tier≥3` 时 +1px。
→ 玩家能数齿数判断"这塔几级了"，不需要点开面板。

### 2.2 敌人：边框 = 护甲，附加标记 = 属性

| 护甲 | 边框画法 | 颜色 |
|---|---|---|
| `light` 轻甲 | 细虚线（1px，2-2 交替） | 灰蓝 |
| `medium` 中甲 | 实线 1px | 灰绿 |
| `heavy` 重甲 | 实线 2px | 深灰 |
| `fortified` 城甲 | **双层实线** | 铁青 |
| `divine` 神圣甲 | 实线 2px + **四角金色刻痕** | 白 + 金 |

| 属性 | 标记 | 位置 |
|---|---|---|
| **飞行** `flying` | 下方 2px 阴影留白（视觉上"浮起来"）+ 两侧各 1px 翼痕 | 本体周围 |
| **BOSS** `isBoss` | 尺寸 ×1.5 + **外圈金色实环** | 整体 |
| **精英** | 右上角 1 个金色星点 | 右上 |
| **窃金抗性** `stealResist > 0` | 一个挂锁字形（非色觉通道） | 左下角 |
| **窃金免疫** `stealResist = 1000` | 挂锁 + 一条斜杠 | 左下角 |

> **为什么窃金抗性要有标记**：它是「钱袋锁」敌人的核心机制（§4.5.2），玩家必须一眼看出"这个偷不动，得补输出塔"。**这是本作最重要的视觉信息之一**，不能只靠怪物名字。

### 2.3 状态帧

用**程序化变形**而不是逐帧绘制：

| 状态 | 表现 |
|---|---|
| `idle` | 基准，每 30 tick 上下浮动 1px（呼吸感） |
| `attack` | 沿朝向偏移 1px + 中心 1 帧白闪 + 出膛口 2×2 亮点 |
| `upgrade` | 外扩 1px 圆环，3 帧内消失 |
| `walk`（敌人） | 左右交替 1px 位移，周期 20 tick |

### 2.4 血条与钱包条（关键）

`engine-dev` 的对象池里已有 500/250/300 三个池，但**条状 UI 应由渲染层绘制，不是精灵**。美术模块只输出**规格**：

| 条 | 位置 | 颜色 | 尺寸 | 重要度 |
|---|---|---|---|---|
| HP | 精灵上方 2px | 红→绿渐变 | 宽=精灵宽，高 1px | 常规 |
| **钱包** | HP 条下方 1px | **金 `#ffc832`** | 宽=精灵宽，高 1px，**有底槽** | ★ **核心机制，必须最醒目** |
| 阻挡 | 精灵脚下 1px | 白 | 1×1 | 常规 |

> 钱包条是**本作的招牌机制可视化**——玩家要能实时看到"这只怪的钱被偷掉多少"。它比血条更能传达游戏的核心。**宁可砍血条也不能砍钱包条。**

### 2.5 无障碍要求（策划案 §6.5）

**任何关键信息不得只靠色相编码。** 每个属性都必须同时有形状/纹理通道：

```
护甲    → 边框画法（虚线/实线/双层/四角刻痕）  ✅ 非颜色通道
塔系    → 轮廓形状                              ✅ 非颜色通道
品阶    → 齿数                                  ✅ 非颜色通道
飞行    → 阴影留白                              ✅ 非颜色通道
窃金抗性 → 挂锁字形                              ✅ 非颜色通道
```

**验收方式**：接触表必须同时输出**灰度版**与**红绿色盲模拟版**，在灰度和色盲版下仍能区分全部属性，才算通过。

## 3. 架构：可替换契约

这是整个方案的**关键工程决策**——占位美术必须是**可插拔**的，接真实美术时只换实现，不改调用方。

```ts
// src/art/source.ts —— 纯 TS，零 Phaser 依赖

export type SpriteState = 'idle' | 'attack' | 'upgrade' | 'walk';

/** 一帧在纹理图集里的位置 */
export interface FrameRef {
  x: number; y: number; w: number; h: number;
  /** 锚点（脚的着地点），用于站位与血条定位 */
  anchorX: number; anchorY: number;
}

/** 图集描述（可序列化为 JSON，交给 Phaser 的 atlas 加载器） */
export interface AtlasSpec {
  imageWidth: number; imageHeight: number;
  frames: Record<string, FrameRef>;   // key = `${id}:${state}`
  meta: { generator: string; version: number };
}

/**
 * ★ 替换点：唯一需要改的地方。
 *   ProceduralSpriteSource —— 现在
 *   AtlasSpriteSource      —— 接真实美术时
 */
export interface SpriteSource {
  readonly atlas: AtlasSpec;
  /** 生成像素数据（RGBA，行优先，宽×高×4） */
  render(): Uint8ClampedArray;
}
```

**接线约定**：`src/render/**` 只通过 `SpriteSource` 读图集与像素，**不得内联任何形状/颜色逻辑**。接真实美术 = 换一个 `SpriteSource` 实现 + 换图集 PNG。

## 4. 可验证性：接触表（Contact Sheet）

**这是本方案里我最看重的一点。**

`tools/art/contact-sheet.ts` 输出一张 PNG，包含：

1. 全部 29 个塔（按 9 系 × 品阶排列），48×48，**4× 放大**
2. 全部 11 类敌人，32×32（BOSS 96×96），**4× 放大**
3. 每个精灵下方标注 `id` 与关键属性
4. 血条/钱包条的示意
5. **灰度版**（同一张图去色）
6. **红绿色盲模拟版**

有了这张图，**"占位美术够不够用"从主观判断变成一次性目视验收** —— 主策划可以直接看图判定，不需要读代码或跑游戏。

技术要求：PNG 编码用 Node 内置 `node:zlib`（deflate）+ 手写 CRC32，**零新依赖**（`package.json` 已冻结）。

## 5. M2 验收标准的修订

策划案 M2 原写「正式像素美术」。美术暂缓后这条无法达成，**必须改**：

| 原 | 改后 |
|---|---|
| 正式像素美术 | ① 占位美术**覆盖全部 29 塔 + 11 敌人**（无缺失、无共用）<br>② `SpriteSource` 替换契约已就位且被 `src/render/**` 实际使用<br>③ **接触表评审通过**：灰度和色盲模拟下仍能区分全部关键属性<br>④ 像素渲染保持无糊边（M0 的 NEAREST + 整数倍缩放结论不被破坏） |

## 6. 后续接真实美术时的迁移路径

```
1. 美术产出图集 PNG + atlas JSON（尺寸/锚点遵循本方案的规格）
2. 新增 AtlasSpriteSource 实现 SpriteSource
3. 改一处绑定：ProceduralSpriteSource → AtlasSpriteSource
4. 保留占位实现（它是"资源丢失时的兜底"与 CI 快照基准）
5. 跑接触表对比，确认视觉信息没有退化（尤其"护甲边框"与"窃金抗性挂锁"）
```

**占位实现不要删。** 它有三个长期价值：CI 里做视觉快照基准、真实资源加载失败时的兜底、以及新增单位的即时可玩性（新单位不必等美术）。

## 7. 与现有代码的关系

`engine-dev` 在 M0 已经写了 `src/render/atlas.ts`（运行时生成占位图集，单纹理 40 帧）与 `src/render/pixel-font.ts`（5×7 位图字体）。本方案**不推翻它**，而是：

- 把生成逻辑从 `src/render/**` **下沉**到 `src/art/**`（纯 TS、可 Node 测试、可输出 PNG）
- 补上本方案的**视觉编码规则**（原实现是按索引循环填色，没有语义编码）
- `src/render/**` 改为**消费** `src/art/**` 的 `SpriteSource`

⚠️ `src/render/**` 属 `engine-dev`，且它**正在运行**（M2 返工）。所以本方案**只交付 `src/art/**` 与 `tools/art/**`**，接线由主策划在 `engine-dev` 收尾后统一安排，避免两个 agent 同时改 `src/render/**`。

## 8. 冻结的编码表（供实现直接引用）

```
塔  id → 系(line) → 轮廓；tier → 齿数
     thief  ◆    archer ▲    mage ⬢    drill ■    beauty ●
     cannon ⬣    worker ▣    sprite ∴    tech ✚

敌  护甲 → 边框：light 虚线1px | medium 实线1px | heavy 实线2px
                  fortified 双层  | divine 实线2px + 四角金刻痕
     flying  → 下方 2px 阴影留白 + 两侧 1px 翼痕
     isBoss  → ×1.5 + 外圈金环
     精英    → 右上角金星
     stealResist>0    → 左下挂锁
     stealResist=1000 → 挂锁 + 斜杠
```

**尺寸**：塔 48×48 ｜ 普通敌 32×32 ｜ 精英 48×48 ｜ BOSS 96×96 ｜ 板条 1px 高
**渲染**：`NEAREST` + **整数倍**缩放（M0 已证明非整数倍会产生 shimmer）

### 8.1 标记尺寸随帧尺寸等比缩放（补充裁决）

**本文档 §2.2 的「2px 留白 / 1px 翼痕」是以 32px 帧为基准写的。** 在更大的帧上固定 2px 会让标记**相对不可见**，因此：

| 帧尺寸 | 翼痕 | 飞行留白 |
|---|---|---|
| 32（普通敌） | 3px | 2px |
| 48（精英 / 塔） | 6px | 4px |
| 96（BOSS） | 9px | 6px |

**等比缩放是正确的解读**（主策划确认）。同一规则适用于所有"按像素数定义"的标记（挂锁、星点、四角刻痕）。

> **一处已修的实例**：改前 `ascendant`（96px，**唯一的飞行 BOSS**）的飞行标记是**反向的** —— 留白带从 56px 变成 65px（它自己的金色外环把 2px 空隙占满了），翼痕带只 +9px。改后翼痕带 **+53px**、留白带 **273→198**（真的空出来了）。
> ⇒ **在"飞行"这个属性最要紧的那只敌人身上，飞行标记原本是失效的。**
