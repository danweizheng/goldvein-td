**`engine-dev` 自报的相关信息**（它标为"根因未定位、人类用 `pnpm dev` 会不会遇到**未验证**"）：

**⚠️ 但主策划看到的不止是音频问题，是整屏空白 + `Uncaught`。** 两者可能同源，也可能不同源。**需要区分**：

1. `Uncaught` 的内容是什么（冒烟工具只打了 `Uncaught` 两个字，**没带 message 与栈** —— 这本身是冒烟工具的一个缺陷，见 C5）
2. 那 404 是哪个资源
3. `Phaser` 版本横幅打出来了 ⇒ 引擎起来了，但**没进 Game 场景**（对比静态路径的 `scenes` 数组里 `Game.active=true`）

**离线线索**：静态路径的 `scenes` 是 `[Boot(active:false), Game(active:true), PixelProbe(active:false)]`。dev 路径下没有这份数据（`hasGame` 未打印），**先查场景有没有跳过去**。

## C. 会误导下一个人的东西（**接手前先看这一段**）

### C1. `tools/bench/out/` 里有 **32 个浏览器 profile 垃圾目录**

`chrome-profile-*` / `smoke-profile-*`。**可整目录删**（该目录是报告输出目录，已被 eslint/vitest 忽略）。

### C2. ★ **像素审计的负对照没跑完，其中一半的数字是错的**

`engine-dev` 自报：

> 第一版只统计全屏金色像素（`goldPixels`），**对照组反而更高（336 vs 320）** ⇒ 说明它数的是 **HUD 金字**，根本没隔离钱包条。**这个数字不要信、也不要引用。**
> 改后的 `goldWorldPixels` **还没验证过**，而且它会被 **★停顿点的金色高亮污染**（底噪 ≠ 0）。**下一个人要用它，必须先跑一次无敌人对照。**

**⇒ 任何基于 `goldWorldPixels` 的视觉断言，在跑过"无敌人对照"之前都不可用。**（这正是铁律 8 第 4 条：先证明测量区域里有信号。）

### C3. 自动化探针要在上线前摘掉

`GameScene.debugState` 与 `window.__DSH_GAME__` 是给冒烟工具读运行时事实用的（暴露 wave/gold/stealEvents），**不是给 UI 用的**。

### C4. 投射物渲染是**刻意的规格偏差**（已写进测试防漂移）

策划案 §8.5 要求「投射物池 500」，而出货场景改为在同一个 Graphics 里批量画 3×3 方块 —— 原因：**art 图集没有投射物帧**（109 帧正好用尽）。500 精灵池路径只存在于 `tools/bench/render-bench.ts`。

**这一条需要主策划最终确认**：是接受这个偏差，还是让 `art-proxy` 补投射物帧。

### C5. ★ 冒烟工具自身的一个缺陷（主策划实测发现）

它在捕获未捕获异常时**只输出了 `Uncaught` 两个字，没有 message、没有栈**：

```
⚠ 异常/错误行：
  Uncaught              ← 就这两个字
```

**⇒ A1 的排查因此被挡住了。** 恢复时**先修这个**（把 `exceptionDetails.exception.description` 与 `stackTrace` 一起打出来），否则 A1 只能靠猜。

> 这与铁律 8 同源：**一个"报错了但不告诉你错什么"的工具，等于没有工具。**

## D. 主策划越权改动（**请裁决保留还是回退**）

### D1. 主策划改了 `src/render/__tests__/no-phaser-text.spec.ts`

**背景**：暂停时该测试是**唯一的红**（`1 failed / 882 passed`）。诊断结论：**池容量没有回归**，是断言本身脆弱 ——

```ts
// 原断言：对 GameScene.ts 的【构造字面量】做正则
expect(gameScene).toMatch(/new SpritePool\(this, ATLAS_KEY, 500/);
expect(gameScene).toMatch(/new FloatTextPool\(this, 300/);
expect(gameScene).toMatch(/new SpritePool\(this, ATLAS_KEY, 250/);
```

可玩路径重写后构造写法变了（实测：敌人池 `250` ✅、飘字池 `300` ✅ 都在；**投射物池 500 不在场景里**，改为由 `tools/bench/render-bench.ts:105` 承担 —— 已核实该处确有 `new SpritePool(this, ATLAS_KEY, 500, 12)`）。

**主策划的改法**：把断言从「对某一行代码长什么样敏感」改为「对**谁负责哪个容量**敏感」——
- GameScene 断言 敌人 250 / 飘字 300
- `render-bench.ts` 断言 投射物 500

**并做了反向验证**：把 GameScene 的敌人池改成 `251` → 该断言**立刻报红**；还原后全绿。

**⚠️ 但这是 `engine-dev` 的独占路径，主策划越权了。** 请裁决：**保留**（它现在是对的且带反向验证）或**回退**（`engine-dev` 自己按它的判断重写）。

> `engine-dev` 已在它的状态快照里记录了这次外部改动（"我的独占路径被外部动过"），处理正确。
